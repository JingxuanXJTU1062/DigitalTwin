# F407HALL 经出料板串口汇聚设计

## 目标

取消 F407HALL 与上位机之间不稳定的 I2C3 链路。F407HALL 改用 USART1 将原有 16 字节 `0x03` 数据帧发送给 F103chuliao05；出料板接收并校验该帧，再通过自己现有的 USART1→上位机 UART5 链路，把原 12 字节 `0x05` 出料帧和最新有效的 16 字节 `0x03` HALL 帧连续发送。上位机在 UART5 上统一解析两种原有帧。

成功标准：正常连接时，PC 端 Modbus 有效位持续显示 `C1 D1`；断开 HALL→出料板串口超过 500 ms 后，出料数据仍保持 `C1`，HALL 数据自动变为 `D0`，不继续上报陈旧数据。

## 数据链路

```text
F407HALL USART1_TX/PA9
        │ 115200, 8-N-1
        ▼
F103chuliao05 USART1_RX/PA10
        │ 接收、校验并保存最新 HALL 帧
        │
F103chuliao05 USART1_TX/PA9
        │ 115200, 8-N-1
        ▼
上位机 UART5_RX/PD2
        │ 解析 0x05 与 0x03 原始帧
        ▼
Modbus 输入寄存器 → PC
```

所有设备必须共地。链路均为单向，不连接反向 TX。

## 串口与接线

- F407HALL：USART1，PA9 为 TX，115200、8 数据位、无校验、1 停止位、无流控。
- F103chuliao05：USART1，PA10 同时作为 HALL 接收端，PA9 保持为上位机发送端；USART 全双工允许收发同时工作。
- 上位机：UART5，PD2 为 RX，配置保持 115200、8-N-1。
- 接线：F407HALL PA9 → F103chuliao05 PA10；F103chuliao05 PA9 → 上位机 PD2；三块板 GND 相连。

## 帧格式

不定义新的应用层帧，不修改模块 ID、长度字段、字节序或 XOR 算法。

### F103chuliao05 原帧

- 总长 12 字节。
- 帧头 `AA 55`，模块 ID `0x05`，载荷长度 `0x07`。
- 最后一个字节为从模块 ID 到最后一个载荷字节的 XOR。

### F407HALL 原帧

- 总长 16 字节。
- 帧头 `AA 55`，模块 ID `0x03`，载荷长度 `0x0B`。
- 内容保持三路霍尔、两路距离和状态字段。
- 最后一个字节为从模块 ID 到最后一个载荷字节的 XOR。

### 出料板发送批次

出料板每个原发送周期先构建自己的 12 字节帧：

- HALL 帧有效且接收时间不超过 500 ms：构建稳定的 28 字节发送快照，内容为 `[0x05帧][0x03帧]`，单次异步发送。
- HALL 帧尚未收到、校验失败或超过 500 ms：只发送 12 字节 `0x05` 帧。

发送期间不修改正在使用的发送缓冲区；新收到的 HALL 帧只更新独立的接收快照。

## 各工程修改

### F407HALL

- 保留 USART1 PA9/PA10 初始化，实际只使用 PA9 TX。
- 将当前 `DistanceTx_Send()` 的16字节组帧结果改由 USART1发送，调用接口和帧格式保持不变。
- 停止初始化和使用作为板间通信的 I2C3；I2C1/I2C2传感器总线不受影响。
- 保留可观察的发送计数、错误计数和最后一帧变量，名称调整为串口含义或新增兼容变量。

### F103chuliao05

- USART1启动单字节中断接收，并在接收完成回调中立即重新挂接下一字节。
- 增加16字节状态机，只接受 `AA 55 03 0B ... XOR` 完整有效帧。
- 记录最新HALL帧、有效标志、接收计数、校验错误计数和最后接收时间。
- 将现有12字节发送缓冲扩展为最大28字节发送快照；发送有效HALL帧时依次放入 `0x05` 和 `0x03` 原帧。
- 发送完成回调继续恢复发送就绪状态；接收链路不因发送而停止。

### 上位机 F407_04

- 不再初始化、轮询 F407HALL 的 I2C3链路。
- UART5继续接收出料板数据；现有通用状态机已经支持 `0x05/12B` 与 `0x03/16B`，两帧连续到达时分别更新出料和HALL数据。
- 保留Modbus寄存器布局和有效位定义，因此PC脚本无需改变。
- 移除或停用过时的 I2C3 HALL调用，避免无设备时20 ms阻塞和BUSY超时。

## 错误处理

- F407HALL发送失败时增加错误计数，下一个50 ms周期继续尝试。
- 出料板只缓存通过帧头、ID、长度和XOR校验的HALL帧。
- 出料板不得把超过500 ms的HALL快照继续转发。
- 上位机现有500 ms新鲜度机制作为第二层保护，未持续收到 `0x03` 帧时清除D路有效位。
- 出料板自身 `0x05` 数据不依赖HALL链路；HALL断线不能阻塞出料数据发送。

## 验证

1. 单元测试验证F407HALL生成的16字节帧仍符合原协议。
2. 单元测试向出料板接收状态机输入有效帧、错误XOR帧和分段字节流，验证仅有效帧更新快照。
3. 单元测试验证有效HALL时发送批次为28字节且顺序为 `0x05` 后 `0x03`；超时后退化为12字节。
4. 构建F407HALL、F103chuliao05和上位机三个工程。
5. 板上观察：HALL发送计数增加；出料板HALL接收计数和28字节发送计数增加；上位机UART5接收计数以及 `g_rx_count_hall_vl6180x` 增加；PC端显示 `C1 D1`。
6. 断开HALL PA9→出料PA10，500 ms后验证PC端为 `C1 D0`。

## 非目标

- 不改变F407HALL03的USART2→上位机链路。
- 不改变另外三块下位机协议、Modbus寄存器地址或PC脚本格式。
- 不增加上位机向F407HALL或出料板的反向控制通道。
